# Timeline

ทุกอย่างที่ต้องทำจากทุกระบบ รวมอยู่ในจอเดียว

ระบบงานแต่ละตัวรู้เรื่องของตัวเองครบอยู่แล้ว — loan รู้ว่าใครครบกำหนด GCMS
รู้ว่าเว็บไหนใกล้หมดอายุ — แต่ไม่มีจุดไหนที่มองเห็นพร้อมกัน และไม่มีอะไรมาบอก
ก่อนถึงเวลา Timeline คือจุดนั้น: ดึงรายการที่มีกำหนดเวลาจากทุกระบบมารวมกัน
เรียงตามความเร่งด่วน เตือนผ่าน LINE / Telegram และส่งคำสั่งกลับไปให้ระบบต้นทาง
ทำเมื่อกดปุ่มบนการ์ด

Hub ไม่เคยเขียนข้อมูลของระบบอื่นเอง — สิ่งที่แสดงบนจอคือสำเนา และทุกการกระทำ
ถูกส่งกลับไปให้เจ้าของข้อมูลเป็นคนทำ

## เอกสาร

| ไฟล์ | เนื้อหา |
|---|---|
| `TIMELINE-PROTOCOL.md` | สัญญากับภายนอก — ระบบที่อยากส่งข้อมูลเข้า Timeline ต้องทำตามนี้ |
| `HUB-DESIGN.md` | สถาปัตยกรรมข้างใน Hub |
| `EXTENDING.md` | ต่อระบบใหม่เข้ากับ Hub |

## ระบบที่ต่ออยู่

`loan` · `gcms` · `account` · นัดหมายที่ Hub ดูแลเอง

ระบบต้นทางประกาศ endpoint สามตัว — `timeline/manifest` `timeline/items`
`timeline/actions` — แล้วเพิ่มเข้ามาที่หน้า `/connections` โดยไม่ต้องแก้โค้ดของ Hub

## ติดตั้ง

ต้องการ PHP 8.0 ขึ้นไป (ใช้งานจริงบน 8.4) · MySQL 5.7 / MariaDB 10.4 ขึ้นไป · Apache ที่เปิด `mod_rewrite`

1. วางไฟล์ไว้ที่ document root แล้วเปิด `/install/` ในเบราว์เซอร์ · ตัวติดตั้งสร้างตาราง
   ทั้งหมด (`install/database.sql` + `timeline.sql` + `chat.sql`) และเขียน
   `settings/database.php` กับ `settings/config.php` ให้เอง — **สองไฟล์นี้ไม่ได้อยู่ใน
   repo** เพราะเก็บรหัสผ่านฐานข้อมูลและกุญแจของระบบ
2. ลบโฟลเดอร์ `install/` ทิ้งเมื่อติดตั้งเสร็จ
3. ตั้ง cron ทุก 5 นาที — ไม่มีตัวนี้ก็ไม่มีการดึงข้อมูลและไม่มีการเตือน

   ```
   */5 * * * * /usr/bin/php /path/to/cron.php >> /path/to/hub-cron.log 2>&1
   ```

4. เพิ่มระบบต้นทางที่หน้า `/connections` · โทเคนของแต่ละระบบ การเชื่อม Telegram/LINE
   และค่าอื่น ๆ ตั้งจากหน้าเว็บ ไม่ต้องแก้ไฟล์

`DEBUG` ใน `load.php` ปริยายเป็น `0` (บันทึกลง log อย่างเดียว) · ตอนพัฒนาตั้งเป็น `2` เพื่อให้
ข้อผิดพลาดแสดงบนหน้าจอ **ห้ามตั้งเป็น 2 บนเครื่องที่ให้บริการจริง**
